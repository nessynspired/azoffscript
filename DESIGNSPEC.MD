# AZ Off Script — Full Website + Portal Design Spec

## Public Brand Site + “The Off Script Room” Creator Portal

## 1. Brand Experience Direction

### Core brand idea

**AZ Off Script** is an Arizona-based creator brand built around real reactions, funny questions, local energy, personality-driven content, hot takes, group chemistry, and off-script moments.

The portal is not a “dashboard.”
The portal is **The Off Script Room** — a private creator clubhouse where members drop clips, share ideas, approve videos, check the run sheet, and feel like they are part of something selected and alive.

### Emotional target

The experience should make people feel:

* “This feels real.”
* “This feels fun.”
* “I was chosen for this.”
* “I know exactly what to do.”
* “I want to come back and see what’s moving.”
* “This is organized, but it does not feel like homework.”

### Design vibe

**Retro Arizona media lounge.**

Not rustic.
Not generic western.
Not corporate SaaS.
Not pink women’s club.
Not childish mascot overload.

The look should combine:

* desert-night contrast
* warm sandstone texture
* cactus mascot attitude
* retro editorial badges
* sticker-style content cards
* mobile-first creator utility
* bold merch-ready graphic language
* playful microcopy
* real operational clarity underneath

---

# 2. Design Directions to Avoid

## Avoid 1: Generic SaaS dashboard

Do not use:

* plain white cards
* boring tables everywhere
* left sidebar + square widgets only
* corporate upload boxes
* generic project-management UI

### Why this fails

It feels like work. The group will avoid using it. Creators do not want another admin dashboard.

---

## Avoid 2: Overly cute scrapbook portal

Do not use:

* too many stickers
* excessive paper textures
* overly feminine colors
* tiny decorative elements everywhere
* cluttered collage layouts for functional screens

### Why this fails

It may look cute in one screenshot, but once real videos, statuses, names, approvals, and calendars appear, it becomes hard to use.

---

## Avoid 3: TikTok clone / social feed clone

Do not build:

* endless feed as the main structure
* everything as a “post”
* weak organization under the hood
* no clear calendar/status system

### Why this fails

The point is not to become TikTok. The portal needs to organize TikToks, clips, ideas, people, and approvals.

4. next thing needed

Do not make users hunt.

---

# 29. Accessibility + Practical UX

Even though it is stylish, it must still work.

## Requirements

* high color contrast
* large tap targets
* readable body text
* no important text embedded only in images
* form errors near fields
* loading states
* saved states
* upload progress
* offline/fail gracefully when possible
* private links warning
* confirmation before delete
* role-based visibility

---

# 30. States to Design

Every major screen needs these states:

## Loading

Use subtle animated sun/cactus pulse.

## Empty

Use mascot and helpful next action.

Example:
**Nothing dropped yet. Be the first to toss something in.**

## Success

Use bright, celebratory but not childish.

Example:
**Dropped. We got it.**

## Error

Use human language.

Example:
**That link looks private. Make sure anyone with the link can view it.**

## Permission denied

Example:
**This room is private. Ask Vanessa for access.**

## Needs attention

Use Sunburst Yellow sparingly.

Example:
**2 clips need your greenlight.**

# 34. Final Design Summary

AZ Off Script should not look like a dashboard.
It should look like a private creator clubhouse with a real operating system underneath.

The public site should sell the brand.
The portal should run the brand.

The experience should be:

* visually memorable
* mobile-first
* easy to share into
* fun to open
* clear to use
* emotionally personal
* operationally serious underneath
* expandable to men, women, couples, Arizona-wide content, merch, sponsors, and events

The final vibe:

**Arizona heat. Real reactions. Off-script moments. Organized chaos, but make it look good.**

## My build recommendation

Give Devin this spec, but do **not** let Devin start with the full app at once. The first build checkpoint should be:

> **Mobile member logs in → taps Drop → pastes/uploads a clip → tags who is in it → Vanessa sees it in the Run Sheet → tagged people can approve it.**

That is the core machine. Everything else can wrap around that.
