Auto-email invite codes to approved applicants

Before: when an admin approved a join submission and clicked
"Convert to invite," the invite code was just copied to the admin's
clipboard. The applicant had no idea they were in unless the admin
manually texted/DMed them. The Join form didn't even collect an email,
so there was no way to auto-notify them.

Now:

1. Join form collects a required email field ("only used to send your
   invite if you're in"). Server validates format; bots get fake success
   on invalid emails (same anti-spam pattern as the rest of the form).

2. New migration: add-join-email-column.sql adds the email column to
   join_submissions. Schema.sql updated to match for fresh installs.

3. When admin clicks "Convert to invite," the app now automatically
   emails the applicant their invite code via Resend (same transport
   already used for admin alerts). The email includes the code, a link
   to /login, and step-by-step instructions ("Tap 'Need access?'").

4. Admin UI shows clear status after the email attempt:
   - "Invite emailed to {email}" with a Resend button
   - "Email didn't send" with the error + a "Try sending again" button
     + a fallback reminder to copy the code and DM manually
   - "No email on file" warning for older submissions without one

5. New API route /api/admin/send-invite-email (admin-only) handles the
   send + can be called again to resend.

6. Admin alert email (to hello@azoffscript.com) now includes the
   applicant's email too, so you can reach out directly if needed.

After deploying, run supabase/add-join-email-column.sql against the
Supabase instance to add the column.
