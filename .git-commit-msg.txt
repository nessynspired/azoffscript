Fix duplicate signature error — use service client for existing-signature check

The "duplicate key value violates unique constraint" error happened because:
1. The existing-signature check used the regular supabase client (with RLS)
2. The RLS policy sig_read_own checks member_id = auth.uid()
3. But member_id is the members.id UUID, NOT the auth user ID
4. So RLS blocked the read, the check returned null
5. The insert tried to add a duplicate, hitting the unique constraint

Fix: use the service role client for the existing-signature check so it
bypasses RLS and can actually find the existing signature.

Also includes a SQL migration (supabase/fix-signature-rls.sql) to fix the
RLS policy itself so client-side reads (use-terms-status hook, TermsGate)
also work correctly. This prevents the woman from seeing "sign the Creator
Release" when she already signed.
